## 1. Problem Statement & UX Gaps Resolved

Prior to Phase 10, several usability and visual issues existed in the sidebar session management:
1. **Generic Titles:** Every session remained titled "New Compliance Session" indefinitely.
2. **Input Instruction Overlap:** Streamlit's native `"Press Enter to submit form"` microcopy overlapped form placeholders.
3. **Alignment & Glyph Inconsistencies:** The active session row prepended a `"▸ "` glyph and applied an orange background tint that altered row dimensions, causing icon buttons (`✎`, `×`) to misalign vertically across rows.
4. **Empty Duplicates:** Clicking "+ New Session" repeatedly created redundant empty sessions without checking if the current session was empty.
5. **No Recency Grouping:** Sessions appeared in an unstructured list without chronological grouping.

## 2. Automatic Session Title Generation Architecture

### 2.1 Generation Contract (`src/core/session_title.py`)
- **Format:** 3–6 words, Title Case, no surrounding quotes, no trailing punctuation, maximum 40 characters.
- **Strict Non-Leakage Invariant:** The title generator receives **strictly** the user's first query and optional router label (`query` + `router_label`). **Retrieved passages and generated answers are strictly excluded from the generator input.** This guarantees that confidential or manager-only document content can never leak into session titles, the sidebar, browser DOM, or audit logs.
- **Dual-Profile Implementation:**
  - **Live Profiles (`dev` / `demo`):** Executes one focused LLM completion with prompt `prompts/session_title.txt` and `max_tokens=16`. The call is tracked against `spend_guard` as a dedicated `"title"` call. If the live call fails, times out, or exceeds budget, it degrades transparently to the deterministic fallback without blocking the answer.
  - **Mock / Offline Profiles:** Uses deterministic keyword extraction: strips question stop words, filters regulatory/noun tokens, and capitalizes the top keywords (or falls back to the first 6 words of the query).
- **Sanitization:** All titles are stripped of control characters, HTML markup, and quotes, and HTML-escaped before presentation.

### 2.2 Re-Titling Decision (3rd Turn Re-Titling)
- **Decision:** Evaluated an optional re-titling mechanism on the user's 3rd question if semantic similarity dropped below a threshold.
- **Outcome:** **Skipped by design.** In conversational compliance workflows, dynamic title changes mid-conversation cause severe UI flicker, disrupt visual muscle memory in the sidebar, and create user confusion about active session context. Manual renames via the pencil button remain the authoritative mechanism for user-driven re-titling.

## 3. Database Schema & Migration

Updated `src/db/migrations.py` and `src/db/repository.py` to persist title provenance:
- **`title_source` (`TEXT`, default `'default'`):** Tracks whether a title is `'default'` ("New Compliance Session"), `'auto'` (generated by LLM/fallback), or `'user'` (manually typed by user).
- **`title_locked` (`INTEGER`, default `0`):** Set to `1` when the user manually renames a session.
- **Overwrite Protection:** An auto-generated title is generated once per session after the first completed answer. If `title_locked == 1`, auto-generation is permanently disabled for that session.
- **Preserved Casing on User Renames:** When a user renames a session, their exact chosen casing is preserved (e.g. `"Escalation runbook"`), while auto-titles are forced to Title Case.

## 4. Sidebar Layout & CSS Engineering (`src/ui/app.py`)

1. **Fixed Top Action:**
   - Dedicated `+ New Session` primary action fixed at the top of the session manager.
   - **Empty Session Protection:** If the current session contains 0 messages, clicking "+ New Session" focuses the existing empty session instead of creating a duplicate.
   - Removed the redundant new session text input; renames are handled inline on the target row.
2. **Chronological Recency Grouping:**
   - Sessions are grouped under **Today**, **Yesterday**, and **Earlier** via `_group_sessions_by_recency()`, sorted newest-first.
3. **Scroll Container:**
   - Placed within a `.sidebar-session-scroll` container capped at `max-height: 380px` with a subtle 4px scrollbar.
4. **Standardized Grid Row:**
   - Each row features a uniform 3-column layout:
     - `[Title Button (Flexible, single-line, text-overflow: ellipsis, full title tooltip)]`
     - `[Rename Button (32px icon '✎')]`
     - `[Delete Button (32px icon '×')]`
5. **Active Row Styling:**
   - Replaced `"▸ "` glyph with a crisp 3px left Safety Orange accent rail (`#FF5F00`) and subtle background tint (`rgba(255, 95, 0, 0.12)`).
   - Zero layout shift: all icon buttons remain perfectly aligned across active and inactive rows.
6. **Inline Rename & Confirmation:**
   - Clicking `✎` replaces the row with an inline text input + Save (`✓`) / Cancel (`✕`) buttons.
   - Clicking `×` prompts inline confirmation: `"Delete [Name]?"` with Delete / Cancel options.
7. **CSS Hardening:**
   - Streamlit form submission helper microcopy hidden via `small[data-testid="InputInstructions"] { display: none !important; }`.
   - Sidebar width capped at 330px with `overflow-x: hidden`.
   - Complete `@media (prefers-reduced-motion: reduce)` support.
